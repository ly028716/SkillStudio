## 3. 产品与架构取舍

| 方案 | 收益 | 代价 | 结论 |
| --- | --- | --- | --- |
| 本地 Web + 单 Node 连接器 | 延续 README；浏览、编辑与运行共用索引和对象 | 必须处理本机认证、路径边界、进程生命周期 | 推荐作为首版 |
| Electron/Tauri 桌面壳 | 系统目录选择、窗口与进程体验更自然 | 引入安装、升级、签名和额外运行时 | 完成本地闭环后再判断 |
| 浏览器纯前端文件工作台 | 部署轻、适合阅读与编辑 | 难以覆盖已有 CLI 运行目标 | 不满足当前完整 MVP |

UI 以共享 Skill 库为中心，不增加“作者模式/使用者模式”开关。选择具体 Skill 后，“阅读 → 编辑 → 校验 → 运行”保留上下文。运行记录和本地连接作为另外两个一级入口；不设统计仪表盘。

建议首先验证“发现 Skill 并用指定宿主加载”的技术链路，同时完成文件安全与浏览；随后交付编辑，再接入真正的运行 UI。这样不会在视觉上承诺尚未验证的运行能力。

## 4. 技术风险及退出条件

- **宿主差异**：0.153.3 是观测版本，不是已认证版本。实测指定 Skill、同名 Skill、引用附件、非标准目录、错误登录状态后建立支持矩阵；失败时只禁用该运行能力，文件工作台仍可用。
- **路径竞争**：realpath 和写入前重检能降低风险，但不能保证阻止所有恶意本地进程在检查后替换目录。本机任意代码执行对手不属于 MVP 完整隔离承诺；不得宣传为安全沙箱。
- **外部写入**：非协作编辑器不遵循应用锁。保存前比对、备份和写后重读用于冲突检测与恢复；Windows 文件占用及突然掉电需要实机验证，不能只凭 rename 宣称绝对可靠。
- **工具执行范围**：连接器只访问注册 Skill 根目录，并不意味着 Codex 只能读取这些目录。运行页必须展示宿主工作目录与实际沙箱配置；Agent 仍可能使用网络服务。
- **日志与隐私**：Skill 内容、提示词与路径可能进入宿主和日志。工作台不默认外传，但调用 CLI 并非离线承诺；首次运行页说明实际调用宿主及其服务。
- **可用性假设**：同一批用户可能同时创作和使用 Skill；用户已确认两者并重，但尚无访谈数据。用两个独立任务测量验证，避免只优化编辑或只优化运行。

- [W3C：WCAG 2.2](https://www.w3.org/TR/WCAG22/)：作为后续可访问性验收目标；概念图不能证明符合标准。
