# SkillStudio UI 与交互设计评审稿

> **历史视觉规格：** 本文及三张概念图基于单宿主定位。基础编辑交互仍可参考，多 Harness 的信息架构和核心界面以 [SkillStudio 多 Harness 产品设计](2026-09-05-skillstudio-multi-harness-design.md)为准，并需重新完成视觉探索。

日期：2026-09-05。依据：[产品需求](2026-09-05-skillstudio-product.md)。状态：布局与视觉待选择；行为规则可独立评审。

## 1. 设计原则

让用户始终知道当前 Skill 来自哪里、正在编辑哪个版本、下一步能否运行。作者与使用者共享 Skill 库，不设置角色切换，不用仪表盘取代真实任务。

每个状态仅强调一个主动作：空库添加目录；详情运行；编辑保存；预检开始运行；运行中停止；失败后查看原因和重试。编辑与运行入口始终可找到，但不同时争抢主按钮。

## 2. 信息架构

| 入口/路由（拟定） | 内容 | 保留上下文 |
| --- | --- | --- |
| `/library` | 搜索、目录和诊断筛选、Skill 列表 | 查询条件、排序、滚动位置 |
| `/library/:skillId` | 阅读、源码、诊断和运行入口 | 选中 Skill、当前标签 |
| `/library/:skillId/edit` | 原文编辑、草稿诊断、保存 | 未保存正文、基准版本 |
| `/runs`、`/runs/:runId` | 最近记录、最终结果、日志 | 记录筛选和日志位置 |
| `/connections` | 根目录、扫描情况、CLI 能力、重新连接 | 展开的问题项 |

“新建 Skill”为库中按钮；“导出/复制路径/复制原文”在详情更多菜单；“添加目录”在目录筛选旁和本地连接页。收藏和最近打开是库内视图，不增加一级导航。

运行预检采用上下文侧面板，运行开始后底部展示结果/日志面板，可进入完整记录。窄屏改为全宽面板，不同时挤入三个窄列。

## 3. 页面规格

### 首次启动与空状态

标题“把你的 Skill 连接进来”，说明“选择本地目录，文件保留在原位置”。主按钮“添加本地目录”，辅助入口“查看最小 Skill 示例”，示例只是说明内容，不预先写用户磁盘。

输入绝对路径后显示解析出的真实路径、可读/可写状态和扫描范围；确认添加后显示进度。扫描完成回到库。未装 CLI 只影响运行，欢迎页不要求先安装或登录宿主。

| 情况 | 文案 | 操作 |
| --- | --- | --- |
| 无根目录 | 尚未添加本地目录 | 添加本地目录 |
| 根目录没有 Skill | 此目录未找到 SKILL.md | 新建 Skill、切换目录 |
| 过滤为空 | 没有符合条件的 Skill | 清除筛选 |
| 扫描部分失败 | 已加载可读取的 Skill，部分目录无法访问 | 查看失败目录、重新扫描 |
| 根被移走 | 无法访问此目录，文件可能已移动 | 重试、移除连接 |

### Skill 库与详情

推荐行为基线：导航 208px、列表 340–390px、详情占剩余宽度。列表行 72–88px：名称第一层、描述第二层、根别名/诊断第三层；同名项必须有路径区分。不为每个条目增加独立阴影卡片。

详情顶部显示 name、description 和来源；状态分成文档校验与宿主可用性。阅读区展示 Markdown，原文独立可见。路径可复制，过长时省略中间部分，并能用键盘聚焦展开完整路径。

“运行”可进入配置；不可运行时保留可见入口及原因，不让用户悬停才知道问题。编辑对只读根禁用并显示“目录只读，可复制内容或切换可写目录”。

### 新建 Skill

轻量对话框包含根、目录名、名称、描述及目标路径预览；字段错误紧邻字段。主按钮“创建并编辑”；创建期间防重复提交。关闭未提交表单时保留到当前页面会话，不创建残留文件。

### 编辑器与诊断

编辑器占工作区域主宽度；诊断为底部可折叠面板，点击定位对应行。阅读预览切换显示，MVP 不强制常驻双编辑窗。

顶部固定保存状态与主动作“保存”；Ctrl+S 只在编辑区域接管并阻止浏览器保存页面。无改动时禁用保存，保存中防重复请求。错误诊断不禁止保存草稿，保存错误单独提示。

冲突栏：“磁盘文件已被其他程序修改，你的草稿仍在这里。”提供“查看差异”“复制草稿”“重新载入”；重新载入再确认。无强制覆盖按钮。关闭连接提醒不会让保存按钮伪装可用。

点击运行而草稿未保存时弹出“先保存再运行”，操作“保存并运行”“取消”。保存后重新预检，不复用旧的就绪状态。

### 运行配置

标题“运行 code-review”，显示来源、内容版本、CLI 版本；依次填写工作目录、任务描述、只读/工作区写入。权限说明贴近该选择，不能在隐藏设置里悄悄提升。

工作目录旁的目录图标若没有真实选择能力应移除，保留文本输入；不展示虚假可点击控件。宿主未发现目标时主按钮不可提交，正文解释所需宿主发现目录，保留复制路径/导出。

预检列表只在需要解释时展开；就绪摘要如“已保存 · 校验通过 · 宿主可用”。开始时按钮进入“正在启动”。双击、重连不产生第二个任务。

### 运行结果与记录

结果摘要优先于原始日志：状态、开始时间、耗时、工作目录、Skill 版本、宿主最终输出。日志提供文本搜索、跟随最新开关、复制可见段；输出包含未识别事件时仍能阅读。

停止 → “正在停止” → 已取消/停止失败。停止失败不显示重试运行，先确认进程状态。前端断线显示“正在重新连接，任务可能仍在运行”；连接器重启显示“运行中断，结果未知”，不显示成功。

超过保留上限时展示“日志已截断”，有缺段时标记缺失序号。外部源变化展示“运行期间源文件变化，结果对应版本可能不一致”。

## 4. 状态矩阵

| 对象 | 状态 | 用户能做什么 | 不可误用的颜色/文字 |
| --- | --- | --- | --- |
| 连接 | 在线/断开 | 重连；断开仍可复制当前草稿 | 不把离线当空库 |
| 文档 | 已保存/未保存/冲突 | 保存或解决冲突 | 未保存不显示已同步 |
| 校验 | 通过/建议/错误/未检查 | 查看详情、编辑 | 通过不等于安全 |
| 宿主 | 可用/不可用/未知/未发现 Skill | 检查连接、外部配置后重试 | CLI 存在不等于可运行 |
| 运行 | 启动/运行/停止中/完成/失败/取消/超时/中断/停止失败 | 按状态查看、停止或重新预检 | 进程完成不等于业务结果正确 |

## 5. 视觉规范建议

视觉方向未选定，以下作为浅色布局的候选 token，不把概念图采样值当成已批准设计系统。深色方案若被选中需单独测量对比度。

| 项 | 建议 |
| --- | --- |
| 字体 | 系统中文 sans；正文 15px/1.6；路径与源码等宽 14px/1.6；不依赖在线字体 |
| 标题 | 页面 28px/1.3、区域 18px/1.4、辅助 13px/1.5 |
| 间距 | 4、8、12、16、24、32px；页面内边距 24–32px |
| 候选色 | 背景 #F8FAFC、表面 #FFFFFF、主字 #0F172A、辅助字 #475569、强调 #4338CA |
| 状态色 | 成功 #166534、警告 #92400E、错误 #B91C1C；同时使用图标和文字 |
| 控件 | 默认高度 40px，图标按钮点击区至少 32×32px；焦点描边 2px，有偏移 |
| 形状 | 控件圆角 6–8px；以留白、对齐、分隔线组织，避免多层卡片 |
| 动效 | 状态过渡约 120–180ms；尊重减少动态效果偏好 |

普通正文对比度目标 ≥4.5:1，关键非文本控件和焦点 ≥3:1；目标符合 [WCAG 2.2](https://www.w3.org/TR/WCAG22/)，实际组合要逐一测量，不能只凭颜色表认定通过。

### 响应式与键盘

- ≥1280px：导航、列表、详情可同时显示；运行配置占详情或侧面板，不形成第四个窄列。
- 960–1279px：折叠导航，列表可隐藏；编辑优先保留至少 600px 内容宽度。
- <960px：库列表/详情单屏切换，运行配置全宽；保留返回与草稿保护。390px 提供可读可操作布局，不另建移动版功能。
- 200% 缩放无主按钮遮挡；到窄视口仍可完成核心流程。代码块可独立横向滚动，页面主体不依赖横向拖动。
- Tab 可到全部操作；对话框焦点约束、Esc 关闭和关闭后焦点恢复；错误摘要可聚焦。日志追加不持续抢屏幕阅读器焦点。
- Ctrl+K 聚焦库搜索，Ctrl+S 保存；在输入法组合阶段不拦截 Enter。不引入未经实现的快捷键标识。

## 6. 三张视觉概念

图片为内置 Image Gen 生成的布局探索，数据均为示例，未作为运行界面验证。按会话展示顺序编号：

| 概念 | 图片 | 结构取舍 |
| --- | --- | --- |
| 01 | [查看概念图](../../design/01-library.png) | 列表与详情并列，查找后继续编辑/运行；横向占用较大 |
| 02 | [查看概念图](../../design/02-studio.png) | 阅读/编辑为中心，长文创作宽度充足；运行配置需再展开 |
| 03 | [查看概念图](../../design/03-console.png) | 说明与运行配置并列，执行前信息充分；需要保证返回库方便 |

概念图评审后的实现修正规则：

- 01 不能只显示“校验通过”就允许启动；须加独立宿主预检。
- 02 中的 Cmd+K 应在 Windows 显示 Ctrl+K；示例 localhost 端口不是承诺。未保存运行必须按 R04 先保存或取消，不能仅提示使用旧版本。
- 03 的目录图标、复制路径视觉和运行控制需对应真实能力；去掉没有功能的控件。独立面板较多，实施时减少边框并保留清晰层级。
- 三图未包含全部错误、空白和窄屏状态；这些状态以本文件与产品需求为准。没有选定图之前，不把任何配色或品牌标识定为最终方案。

## 7. 设计验收清单

- [ ] 用户选定或调整主布局；作者与使用者两条任务均可完成。
- [ ] 库、创建、编辑、冲突、运行预检、结果、本地连接均有默认/加载/空/错误状态。
- [ ] 每个按钮的提交条件、失败文案、恢复动作都有对应需求。
- [ ] 1440×1024、1024×768、390×844 与 200% 缩放人工检查。
- [ ] 源截图和实现截图在相同视口、相同状态并列比较，修正偏差。
- [ ] 键盘、焦点和屏幕阅读器检查；概念图不能代替这些测试。
